# Devbox v2 — Observabilité : spécification fonctionnelle

## 1. Daemon et base de données

### 1.1 Daemon (`spydog`)
Processus Rust, un seul par conteneur.

- **Écoute** une socket Unix datagram : `~/.local/share/spydog/spydog.sock`.
- **Reçoit** des datagrammes JSON (newline-delimited) émis par le client.
- **Enrichit** chaque événement : `project` (racine git du `cwd`), `branch` (branche git courante), `session_id` (généré au démarrage du daemon).
- **Batche** en mémoire puis **flush** vers SQLite (WAL), par intervalle (ex. 1 s) ou seuil de N événements.

**Cycle de vie**
1. **Démarrage** : les `--init-hooks` du `distrobox create` lancent le daemon en détaché à chaque démarrage du conteneur, via `runuser` (tourne en utilisateur), **hors** du garde `.devbox-initialized`.
2. **Anti-doublon** : le daemon tente de binder la socket ; si elle est déjà prise, il s'arrête → un seul daemon par conteneur.
3. **Fonctionnement** : boucle lecture → enrichissement → batch → flush SQLite.
4. **Arrêt** : meurt avec le conteneur (aucun service hôte) ; redémarre au prochain démarrage du conteneur.

### 1.2 Client (`spydog-log`)
`spydog-log <source> <type> [payload-json]`

- Ajoute automatiquement `ts` (epoch ms) et `cwd` (répertoire courant).
- `sendto()` fire-and-forget : non bloquant (~µs).
- `payload-json` optionnel ; s'il est absent, lu depuis `HERDR_PLUGIN_EVENT_JSON` (cas herdr).

### 1.3 Base SQLite
- **Fichier** : `~/.local/share/spydog/events.db` (hors git), mode WAL.
- **Table unique** `events`, append-only :

| Colonne | Type | Contenu |
|---|---|---|
| `timestamp` | INTEGER | epoch ms |
| `source` | TEXT | `fish\|nvim\|pi\|yazi\|herdr\|kitty` |
| `type` | TEXT | `command\|shortcut\|tool_call\|nav\|open\|commit\|…` |
| `payload` | TEXT (JSON) | données propres au hook |
| `cwd` | TEXT | répertoire courant |
| `project` | TEXT | racine git dérivée du `cwd` |
| `branch` | TEXT | branche git courante |
| `session_id` | TEXT | identifiant de session du daemon |

### 1.4 Distribution
- Projet git **spydog** : un crate avec deux binaires (`spydog` = daemon, `spydog-log` = client), installés dans le `Containerfile` via `cargo install` (installe les deux binaires du crate en une fois).
- La devbox ne versionne **que les hooks** (fish, nvim, yazi, herdr, kitty) — jamais le binaire.

## 2. Hooks

### 2.1 fish
| Hook | Déclenchement | Transmet |
|---|---|---|
| `fish_preexec` | avant exécution d'une commande | commande brute, ts début |
| `fish_postexec` | fin d'exécution d'une commande | commande brute, durée (ms), exit code, cwd |
| `fish_command_not_found` | commande inconnue | commande tentée |

```
{"type":"command_start","payload":{"cmd":"git push"}}
{"type":"command","payload":{"cmd":"git push","duration_ms":1234,"exit_code":0}}
{"type":"command_not_found","payload":{"cmd":"gti push"}}
```

### 2.2 nvim
| Hook | Déclenchement | Transmet |
|---|---|---|
| wrapper `Nmap`/`Vmap`/`Nvmap` | utilisation d'un raccourci défini via ces helpers | lhs, desc, mode, ft, filename |
| paste (`TextYankPost` + put `p`/`P`) | collage en normal/visual | texte collé, ft, filename |
| `BufWritePost` + delta | `:w` | diff unifié vs contenu au dernier save (± contexte), ft, filename |
| `BufEnter` | ouverture d'un fichier | filename, ft |

```
{"type":"shortcut","payload":{"lhs":"<leader>ff","desc":"find files","mode":"n","ft":"lua","file":"init.lua"}}
{"type":"paste","payload":{"text":"...","ft":"lua","file":"init.lua"}}
{"type":"save_delta","payload":{"ft":"lua","file":"init.lua","hunks":[{"added":["..."],"removed":["..."]}]}}
{"type":"open","payload":{"file":"init.lua","ft":"lua"}}
```

### 2.3 pi
Aucun hook, import des journaux de session `.jsonl` dans un second temps.

### 2.4 yazi
| Hook | Déclenchement | Transmet |
|---|---|---|
| `ps.sub("cd")` | changement de répertoire | cible, cwd |
| `ps.sub("open")` | ouverture d'un fichier | url, cwd |
| `ps.sub("move"\|"delete"\|"rename")` | opération fichier | source, cible |
| `ps.sub("yank"\|"bulk")` | sélection | cible(s) |

```
{"type":"open","payload":{"url":"/path/to/file.md"}}
{"type":"cd","payload":{"url":"/path/to/dir"}}
```

### 2.5 herdr
`herdr-plugin.toml` : `[[events]] on = "<event>" command = ["spydog-log", "herdr", "<event>"]` ; payload = `HERDR_PLUGIN_EVENT_JSON`.

| Événement | Transmet |
|---|---|
| `pane.focused` / `tab.focused` / `workspace.focused` | id cible |
| `pane.created` / `pane.closed` | pane_id, workspace_id |
| `tab.created` / `tab.closed` | tab_id, workspace_id |
| `workspace.created` / `workspace.closed` | workspace_id |
| `layout.updated` | PaneLayoutSnapshot |

```
{"type":"pane.focused","payload":{"pane_id":"3","workspace_id":"1"}}
```

### 2.6 zoxide
Aucun hook, import de l'historique dans un second temps.

### 2.7 kitty
Pas d'événement natif « touche appuyée » → interception par **wrapper kitten** unique : chaque `map` est réécrit en `map <key> kitten spydog-shortcut <key> <action>` ; le kitten loggue puis rejoue l'action via `boss.combine()` (même chemin que l'appui d'origine).

| Hook | Déclenchement | Transmet |
|---|---|---|
| wrapper kitten `spydog-shortcut` (chaque `map`) | utilisation d'un raccourci kitty | key (combinaison), action rejouée |

```
{"type":"shortcut","payload":{"key":"alt+u","action":"kitten hints --type url"}}
```

## 3. Analyse post-log (ébauche)

- **Commandes** : top N fréquentes / les plus longues → alias, abréviations, scripts ; typos (`command_not_found`) → autocorrections.
- **Raccourcis** : raccourcis nvim/kitty jamais utilisés → nettoyage ; séquences récurrentes → raccourci composite.
- **Navigation** : chemins les plus fréquents (zoxide) → bookmarks, raccourcis yazi, workspaces herdr.
- **Snippets** : hunks récurrents (paste + delta) → templates/snippets, structures de fichiers type.
- **Agents / pi** : tool calls les plus fréquents → optimisation du workflow agent ; coût/tokens → choix de modèle.
- **Workflow global** : corrélation commandes ↔ tool calls ↔ raccourcis → tâches récurrentes de bout en bout à scripter.

## 4. Améliorations possibles

### 4.1 Keystrokes (étude différée)
Deux pistes :
1. **Firmware custom du clavier** : le clavier émet lui-même un datagramme vers le daemon. L'USB HID ne transporte pas d'UDP nativement → RAW HID/VIA ou canal série. Indépendant de l'affichage → favorisé.
2. **Niveau display/terminal** : capture au niveau du serveur d'affichage (moins portable).

Si implémenté : **histogramme de fréquence** (jamais le contenu). Usages : touches mortes, séquences fréquentes → nouveaux raccourcis.
