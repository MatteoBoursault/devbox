Environnement : pi tourne dans la devbox, un conteneur podman/distrobox (Arch Linux). Le home ~/.local/share/devbox-home est un repo git versionné (MatteoBoursault/devbox) ; l'image des outils est construite par Containerfile. Entrée : kitty herdr ; tout se passe dans le terminal. <!-- created=2026-08-29, last=2026-08-29 -->
§
Pi dans la devbox : config dans ~/.config/pi (PI_CODING_AGENT_DIR posé dans config.fish), extensions npm déclarées dans .config/pi/settings.json (pi-hermes-memory, pi-subagents, pi-web-access, pi-mcp-adapter, rpiv-ask-user-question). Mémoire de l'extension dans .config/pi/pi-hermes-memory/ (MEMORY.md, USER.md, failures.md, skills/) : versionnée dans le repo ; sessions.db* et .config/pi/sessions/ non versionnés (chemins absolus + churn). omp = autre harnais LLM (.config/omp, branché sur herdr). <!-- created=2026-08-29, last=2026-08-29 -->
§
Reproductibilité devbox : toute modification d'outil, config ou commande doit être renseignée dans Containerfile, justfile ou README.md (commandes) pour survivre à la recréation de l'image/du conteneur ; une modif faite à la main dans le conteneur est perdue. Déploiement : podman build, puis distrobox create --home ~/.local/share/devbox-home (les clés SSH et secrets de l'hôte sont montés en lecture seule), init-hook = clone du repo + just setup. <!-- created=2026-08-29, last=2026-08-29 -->
§
L'extension pi-hermes-memory a un store de recherche sqlite (table memories) qui garde des doublons des fichiers markdown (USER.md, failures.md). Pour vider complètement la mémoire (suppressions via memory_remove), il faut supprimer chaque entrée deux fois : une fois dans le fichier markdown, une fois dans la table sqlite ; sinon memory_search continue de remonter d'anciennes entrées. <!-- created=2026-08-29, last=2026-08-29 -->
